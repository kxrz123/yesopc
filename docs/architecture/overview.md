## 架构概览（Web + App + 招聘 + 社交）

### 端与模块

- **Web 官网（`apps/web-site`）**
  - 重点：SEO、内容展示、落地页、转化
  - 数据来源：`cms`（内容）、`jobs`（职位列表）等
- **Web Admin（`apps/web-admin`）**
  - 重点：权限、表格/表单、内容发布、审核与回滚
  - 主要操作：`cms`、`media`，以及部分 `jobs/social` 运营能力
- **Flutter App（`apps/app`）**
  - 重点：一致体验、内容流、社交互动、招聘浏览与投递

### 服务边界（建议）

- **`gateway`**
  - 统一鉴权（JWT/Session）、限流、灰度、路由与聚合（必要时做 BFF）
- **`user`**
  - 用户体系、管理员体系、RBAC 权限、账号安全
- **`cms`**
  - 首页配置（区块顺序/卡片内容）、文章/洞察、活动等内容模型
  - 建议内置：草稿/发布/回滚 + 审计日志
- **`media`**
  - 上传与对象存储、图片处理、CDN、回调
- **`jobs`**
  - 职位、公司、投递、简历（附件走 `media`）
- **`social`**
  - 动态、评论、点赞、关注、通知事件产出
- **按需启用**
  - `search`：职位/内容/用户搜索（ES/Meili/OpenSearch）
  - `notify`：站内通知/推送
  - `realtime`：WebSocket（聊天/在线状态）

### 数据与事件（建议）

- **强一致交易流**（投递、权限变更）走同步 API。
- **弱一致通知流**（点赞通知、投递状态通知）走事件（MQ）+ 异步消费。
- **搜索**与**推荐**建议做“旁路系统”，避免侵入核心库表与链路。
